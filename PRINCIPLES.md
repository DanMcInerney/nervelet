# Nervelet principles

Nervelet is an experimental library that connects an agent to a continuous environment through a small, explicit observation and command boundary. Its design can evolve as experiments reveal simpler, faster or more flexible boundaries. It should make control loops more reliable without becoming another planner, agent runtime or simulator.

1. **The environment continues while the agent thinks.** Acquisition, communication, local controllers and admitted jobs do not depend on inference completing. The environment adapter owns those mechanisms; Nervelet coordinates their delivery to the agent.
2. **Give each concept one owner.** The native harness owns sessions, reasoning, tools, compaction and native processes. The bridge owns its received goal, lifecycle, observation delivery and command history. The adapter owns domain schemas, sensing, command admission and execution. Private authored code and notes stay in the existing workspace.
3. **Deliver evidence, not implied freshness.** Preserve acquisition and receipt clocks, sample validity, exact received goals and source identity. Coalesce replaceable samples; retain reliable events until acknowledged. A tool response, a new timestamp or an older image redelivery must not invent a fresh observation.
4. **Separate intent from outcome.** Command admission, physical completion, cancellation and uncertainty are distinct. Compatible batches preserve each operation's outcome. Dependent actions belong in ordered jobs or routines. Reconciliation must not replay an uncertain mutation.
5. **Keep predictable work local.** A model need not think through every servo update or known waypoint. Environment-owned control and permitted agent-authored routines can continue between turns. Jev, a general agent or another controller belongs where its judgment adds value; cheap deterministic code remains a valid baseline.
6. **Authority survives no stale response.** Ownership, received-goal versions and cancellation checks apply to every effect, including scripts. Stop and cancellation remain responsive during inference, waits, capture and compaction. Ordinary chat is not an objective replacement, and loss of radio is not automatically loss of valid local control.
7. **Stay domain-neutral.** An environment may be a robot, an API, a simulation or several composed sources. The core requires no camera, pose, cargo, actuator or simulation clock. Generate tools and instructions from canonical profiles instead of maintaining competing schemas.
8. **Bound resources and expose pressure.** Bound queues, retained receipts, jobs, media and storage. Preserve unread evidence and report backpressure. Do not expand permissions or silently substitute a model, transport or observation to keep a demonstration running.
9. **Measure the layer being changed.** Compare matched task, sensing, local execution and resource budgets. Preserve capable route/routine baselines. Simulated inference delay is an architecture fixture, not a native-model benchmark. Record actual observations, model/tool timings, execution outcomes and costs before claiming a faster or cheaper useful loop.
10. **Qualify claims separately.** Deterministic contracts, native harness behavior, application integration, autonomy and hardware each need their own evidence. A passing fixture or real protocol encoding establishes only what it exercised.

The [design](DESIGN.md), [DroneRTS application contract](docs/dronerts.md) and [validation record](docs/validation.md) define implemented behavior and qualification. These principles do not replace their contracts or promote proposed behavior to tested behavior.

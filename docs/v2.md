# Embedding and drivers (v0.2)

**Recent additions:** [Payload limits, canonical instructions, packing and optional emergency attention](improvements.md) extend this contract. Defaults keep attention disabled and command arguments retained. The older API and driver import paths below remain supported.

The TypeScript refactor implements Phases 0–4 of [the handoff](../NEXT-DESIGN.md). The deterministic protocol and compatibility tests pass. Native driver qualification remains incomplete; [validation](validation.md) separates the evidence. There is one evolved `Bridge`, not a second legacy loop.

## Direct embedding

```ts
import { Bridge, createHandlers } from 'nervelet';
import { createDemoEnvironment } from 'nervelet/demo';

const bridge = new Bridge(createDemoEnvironment(), 'Inspect the bench.');
await bridge.start();
const tools = createHandlers(bridge, { stop: false });
// Hand this bound object only to the already-authenticated actor.
const observation = await tools.call('step', {});
// The host retains goal and shutdown authority.
await bridge.close();
```

An existing host can supply `environmentOwnership: 'borrowed'`; it starts and closes its environment. Bridge closure still requests actor-scoped domain Stop, but does not close borrowed handles. `goalProvider.get()` supplies an already-received `{text, version, status}` record. Optional `subscribe()` reports explicit received replacements. `receiveGoal(record)` preserves the host's version; `updateGoal(text, expectedVersion?)` is for a standalone owner. Serialize goal replacements and handle rejection; ordinary messages do not call either method. A missing goal permits observation and gates commands. There is no automatic mission completion check.

`createHandlers()` exposes `step`, `cancel`, `describe`, and (unless withheld) `stop`. `delegateGoal: true` adds version-checked `setGoal`; it cannot override an injected provider. The tool schemas and required instructions come from the environment's canonical profile. Command schemas use JSON Schema draft-07 and Ajv. Invalid command arguments receive individual receipts; invalid request/wait syntax executes nothing.

`loopRef` is routing data. A bound handle is a capability: authenticate before granting it or use `authorize`. Never select another actor from a model-provided ID. `describe` exposes only bounded profile, commands and status. There is no arbitrary file, shell or artifact reader.

## Environment contract

The existing `Environment` interface remains usable. The additions are optional:

| Member | Owner and meaning |
| --- | --- |
| `changes` | Environment-owned monotonic sequence and synchronous subscription; required for conditional waits |
| `snapshot(after, signal)` | Cheap, non-consuming state/jobs and unread event peek |
| `capture(signal)` | Final bounded acquisition of typed images, once per observation |
| `reconcile(command, signal)` | Authoritative resolution of uncertain admission; never replay a command |
| `cancel` / `stop` result | `{status: confirmed | stopping | unknown, reason?}` |
| `CommandContext.assertCurrent()` | Bridge guard, called immediately before each effect after asynchronous preconditions |

`assertCurrent` is optional in the TypeScript type for old direct callers; Bridge always provides it. Adapters must also check the signal, ownership, resource claims and command-specific evidence at the final effect boundary. This is cooperative execution, not a sandbox for arbitrary JavaScript. Device deadlines, watchdogs, jobs and physical stop stay with the environment. Move CPU-heavy encoding to an environment worker; the core accepts already-encoded bounded images.

`ObservationStore.changes` signals sample/state replacements without waking inference. Its latest slots coalesce; its reliable queue rejects overflow. `wake()` covers changed jobs. Existing demo and serial adapters expose notifications. Serial wire protocol, connection IDs, startup Stop and watchdog behavior remain unchanged.

For old adapters returning `void` from controls, the result is explicitly `unknown / legacy_adapter_no_confirmation`. The legacy successful-promise goal transition remains compatible; it is not physical confirmation. The shipped adapters now return confirmed outcomes only after their existing simulation/device confirmation. Timeout/disconnect outcomes are unknown. `reconcile(id)` resolves an uncertain receipt and requires recovery acknowledgement. `reconcileControl()` retries the idempotent domain Stop to resolve an unconfirmed goal transition. A known adapter fault otherwise remains gated until the application reconciles/restarts it.

## Protocol and delivery

`Bridge.step()` still accepts v0.1 inputs and returns their compatibility envelope. Shared tool handlers produce protocol 2. `deliveredMs` remains an assembly-time alias; `assembledMs` is the new name, not proof of model receipt. V2 adds `schemaVersion`, `loopRef`, `generation`, typed attachments, wait state and control outcomes. Acquisition clocks and host receipt timestamps remain separate.

Echo `seen` only after actual delivery. Events are peeked, then consumed only through the acknowledged included slice. V2 adds stable epoch-scoped event IDs and `redelivered` hints; a high-water cursor bounds tracking. Unacknowledged command results remain in v2 observations within receipt retention. Old/expired command IDs never execute again. Same-ID/same-payload retries return known receipts even while the loop is gated. Unknown receipts are never evicted to admit more work.

Context loss calls `refresh(reason)`, advancing recovery generation and gating new effects. Recovery supplies exact profile, goal, current state, active job arguments and an optional bounded note. Old acknowledgements cannot clear a new generation. API history rotation does this automatically between complete exchanges. Native drivers rely on native lifecycle events; attached CLI/MCP uses installed marker hooks. Undetectable recovery drivers must declare `recovery: 'repeat'`, causing full instructions at every boundary.

`checkpoint` requires a host-provided `saveCheckpoint(text)` callback, which must store plain text atomically. Read it back with `note()`. The CLI keeps the existing `working.md` convention. Checkpoints never update goals, permissions or sensor evidence. Core records remain in memory; there is no crash-durable receipt/event store. A new epoch still requires authoritative executor reconciliation.

## Conditional waits and parking

```ts
await tools.call('step', {
  seen: lastBundle.id,
  goalVersion: lastBundle.goal.version,
  wait: {
    until: [{ kind: 'event', type: 'message' }],
    reviewMs: 600_000
  }
});
```

This ten-minute wait requires handlers configured with `waitMode: 'park'` by a managed host. Attached handlers reject waits beyond their declared hold limit before effects. Legacy `waitMs` keeps its 30-second maximum and cannot be combined with commands; v2 `wait` can. The logical deadline starts before admission and is never extended by transport retries.

Conditions form an OR-list of at most eight: `event`, `jobTerminal`, `threshold` (`gt/gte/lt/lte`), and `change` with a deadband. Numeric fields must be named in `profile.waitFields`, with a source, optional path, and maximum receipt age. Invalid/stale values do not match. The environment remains responsible for source acquisition-age guarantees; receipt age cannot prove acquisition freshness. Already delivered events do not repeatedly wake new waits. Event matching peeks up to eight pages without consuming mail; larger backlogs return an explicit `event_backlog` wake to avoid starvation. Goal changes, faults and Stop bypass filters.

`Supervisor` owns one active turn and latches a ready wait during the closing response. A direct API driver parks between HTTP calls; native drivers may need one closing response. No periodic inference is used while parked. Ignored parking and unexpected finals are bounded by tool/turn/continuation limits. Another ordinary step supersedes the wait. Cancellation invalidates its token. No MCP notification schedules a model.

Default supervisor ceilings are 100 host turns, 128 Nervelet calls per turn, one unexpected-final continuation, five minutes per turn and one hour of active work (parking excluded). Configure them for the application. Observed model calls and cost have optional budgets; unavailable native counts are labeled unavailable. Native internal tool counts are not inferred from host turns. Exhaustion requests domain Stop without spending another model call on a summary. There is no automatic retry of native auth, permission or session failures.

## Transports and drivers

| Import | Behavior |
| --- | --- |
| `nervelet/codex`, `nervelet/claude-code` | Existing installers; their meaning is unchanged |
| `nervelet/mcp` | `mcpTools` for a host's existing server; optional official SDK server, stdio and authenticated loopback HTTP |
| `nervelet/drivers/codex` | App Server thread/turn driver; borrowed initialized client by default |
| `nervelet/drivers/claude-code` | Official TypeScript SDK, one persistent `query()` with streaming input |
| `nervelet/drivers/api` | Explicit chat-completions endpoint/provider/model; native `fetch`, no MCP required |
| `nervelet/recorded` | Finite matching-action replay; divergence is rejected |

Install only selected optional peers: `@modelcontextprotocol/sdk@1.30.0` and, for Claude, `@anthropic-ai/claude-agent-sdk@0.3.273`. Core imports require neither. `connectAppServer({command,args})` explicitly launches an owned process; no process is spawned when borrowing a client. Closing a Codex driver never closes a borrowed client. Shared native processes must retain their host's actor/session permissions and quota enforcement.

Codex uses the host's role-bound MCP server via `connectTools`, or its own authenticated loopback endpoint. Claude uses an in-process MCP server. Neither transport creates another environment. `nervelet mcp --cwd DIR` exposes an already-running IPC bridge over stdio; it never opens another device connection. Its attached waits remain bounded and have no host wake guarantee. CLI stdout remains a text-only compatibility path and rejects image-bearing observations; use MCP or an image-capable API driver.

Both native drivers require an explicit model, working directory and permission configuration. They preserve native reasoning/tools/compaction. No Nervelet engineer, planner or auxiliary model is enabled. Model rerouting/fallback is reported as a failure when exposed by the native protocol. No library fallback model is selected. Harness-internal behavior still requires live qualification.

API mode retains complete assistant/tool pairs (including rejections and concurrent `busy` results), preserves opaque provider message fields, and rotates bounded history with authoritative recovery. One-JSON-action mode accepts only complete `{op,args}` objects; optional JSON constraints must be supported by the chosen endpoint. Partial/malformed output executes nothing; protocol retries are bounded. Unsupported images, changed returned model IDs, auth errors and rate limits fail explicitly. Use exact provider model IDs; aliases that return a different ID are intentionally rejected. Image content follows all paired tool results in a multimodal observation message.

## Bounds, examples and remaining work

New defaults: recovery 32 KiB, media 4 MiB decoded / four images, 128 jobs, checkpoint 1 KiB, logical review at most 24 hours. Ordinary text remains 32 KiB; typical measured demo output is much smaller. Required recovery records that cannot fit are rejected. V0.1 note reads retain their 4 KiB compatibility limit. Profile changes require a restart/reconciliation rather than a live catalog swap.

`trace` reports bounded records for assembly (including known acquisition/receipt times), acknowledgement, admission, observed job completion, wait/wake, control and turn submission. The application owns the nonblocking bounded sink. No reasoning text is collected. Delivery to a transport, model submission and acknowledgement remain distinct.

- [API feed](../examples/api-feed/monitor.ts): no robot schema; exact endpoint/provider/model required.
- [Managed Claude](../examples/managed/claude-code.ts) and [Codex](../examples/managed/codex.ts): opt-in inference examples with bounded simulated tasks.
- [Six-pilot fixture](../examples/dronerts/pilots.ts): borrowed environments, per-pilot goals, images, mail, quotas and one movement writer. No DroneRTS gameplay/session migration.

Deferred optional capabilities: reusable sequence/pinned-routine helpers, durable core store, engineer and Python device adapter. Actual native long sessions, image understanding, repeated compactions, hardware and deployed DroneRTS performance remain qualification work. See [the recorded results](validation.md).
